# TermLens 需求规格文档（requirements.md）

版本：v1.0　日期：2026-09-01　状态：已确认，进入设计阶段
上游依据：`docs/任务文档.md` 中的硬性约束 C-01 ~ C-18 与决策 D1 ~ D12

---

## 1. 产品定位

TermLens 是一款 Windows 桌面端知识生产力工具，采用**双形态架构**：

- **对外形态（Public Mode）** —— 复刻 typeless：语音转文字、题目简单学习、自动排版。这是默认启动形态，也是对外展示的完整产品。
- **扩展层（Extension Layer）** —— 叠加在 typeless 底座之上的增量能力：专业术语自动识别与解释（重点覆盖马克思主义理论术语）、会议自动录音录屏。对外形态下可见可用。
- **对内形态（Developer Mode）** —— 隐藏形态，需显式解锁。解锁后额外开放自动解题、全屏 OCR 术语识别、防录屏隐蔽、自带 Key 的 AI 聊天客户端。未解锁时这些功能在 UI、菜单、快捷键中完全不出现。

第一阶段只交付 Windows 桌面端，架构须为手机端与跨设备同步预留接口。

## 2. 功能需求

### FR-1 语音转文字（对外形态，复刻 typeless 核心）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 支持麦克风实时录音，显示波形与计时 | P0 |
| FR-1.2 | 支持导入本地音频文件（mp3 / wav / m4a / flac）转写 | P0 |
| FR-1.3 | 支持全局快捷键一键开始/停止口述录音（默认 `Ctrl+Shift+D`，可改） | P0 |
| FR-1.4 | 转写引擎经 LLM/ASR Provider 抽象层调用，Key 与 Base URL 用户可改 | P0 |
| FR-1.5 | 转写结果流式输出，边说边出字 | P1 |
| FR-1.6 | 支持中英文及中英混说 | P0 |
| FR-1.7 | 转写稿自动保存为会话记录，可检索 | P0 |
| FR-1.8 | 支持说话人分离（多人对话场景标注 Speaker 1/2/…） | P2 |

### FR-2 题目简单学习（对外形态）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 用户可粘贴或导入题目文本，系统给出讲解式解答（含思路、步骤、结论） | P0 |
| FR-2.2 | 支持从题目中提取知识点，生成要点卡片 | P1 |
| FR-2.3 | 支持基于题目生成同类练习题 | P2 |
| FR-2.4 | 解答中出现的专业术语自动接入 FR-4 术语解释能力 | P0 |
| FR-2.5 | 题目与解答存入学习历史，支持复习 | P1 |

> 注：FR-2 是「学习」定位，输出讲解过程；FR-6 开发者模式的「自动解题」是「快答」定位，直接给答案。两者分离，互不干扰。

### FR-3 自动排版（对外形态）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 将口述得到的散乱文本自动整理为结构化文稿（标题层级、段落、列表） | P0 |
| FR-3.2 | 自动去除口语赘词（嗯、那个、然后就是）与重复语句 | P0 |
| FR-3.3 | 自动补全标点与断句 | P0 |
| FR-3.4 | 提供多种排版模板：会议纪要 / 技术文档 / 学习笔记 / 邮件 / 微博文案 | P1 |
| FR-3.5 | 支持导出 Markdown、Word（docx）、纯文本、PDF | P1 |
| FR-3.6 | 排版结果与原始转写稿可左右对照，支持逐段回溯 | P2 |

### FR-4 专业术语自动识别与解释（扩展层，核心差异化）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 自动识别文本中的专业术语与概念性内容，无需用户手动选词 | P0 |
| FR-4.2 | 识别到的术语自动加视觉标注：加深颜色 + 底部虚线（默认），或描边框（可选样式） | P0 |
| FR-4.3 | 鼠标悬停术语：颜色进一步加深，并在 300ms 内弹出浮层显示简释（1~2 句） | P0 |
| FR-4.4 | 点击术语：展开侧边详解面板，显示定义、背景、关键要点、相关概念 | P0 |
| FR-4.5 | 详解面板内支持多轮追问，每个术语维护独立会话线程 | P0 |
| FR-4.6 | 详解中出现的子概念同样自动标注，可继续悬停/点击/追问，递归无层数上限 | P0 |
| FR-4.7 | 提供概念面包屑路径（父术语 → 子概念 → 孙概念），可回退任一层 | P0 |
| FR-4.8 | 内置领域术语库，首批重点覆盖马克思主义理论术语（剩余价值、生产关系、辩证唯物主义、异化劳动、资本有机构成、上层建筑、historical materialism 等） | P0 |
| FR-4.9 | 术语库按领域分包，用户可开关领域、可自建自定义术语与解释 | P1 |
| FR-4.10 | 解释来源三级瀑布：本地术语库精确命中 → SQLite 缓存命中 → LLM 实时生成并回写缓存（决策 D6） | P0 |
| FR-4.11 | 术语识别与解释在内置阅读器内为精准 DOM 标注模式（无 OCR 误差） | P0 |
| FR-4.12 | 术语解释支持难度分级（入门 / 进阶 / 专业），用户可切换 | P2 |

### FR-5 会议自动录音录屏（扩展层）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 自动检测会议场景（Zoom / Teams / 飞书 / 钉钉 / 腾讯会议 / 微信 进程在前台且音频活跃） | P0 |
| FR-5.2 | 检测到会议后按开关策略自动开启录音与录屏 | P0 |
| FR-5.3 | 提供三态总开关：**自动 / 手动 / 关闭**；录音与录屏各自独立开关 | P0 |
| FR-5.4 | 自动模式下开始录制前弹出可取消的通知（默认 5 秒倒计时），避免无感知录制 | P0 |
| FR-5.5 | 同时采集麦克风与系统声音（可分别开关） | P0 |
| FR-5.6 | 会议结束（进程退出或音频静默超阈值）自动停止并落盘 | P0 |
| FR-5.7 | 录制文件本地存储，路径用户可改，支持容量上限与自动清理策略 | P1 |
| FR-5.8 | 会议录音自动接入 FR-1 转写 → FR-3 排版为会议纪要 → FR-4 术语标注，形成完整链路 | P0 |
| FR-5.9 | 首次启用时必须显示合规提示（录制他人需事先告知并取得同意） | P0 |

### FR-6 开发者模式（对内形态，默认隐藏）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-6.1 | 通过设置页隐藏入口解锁（连续点击版本号 7 次 + 输入开发者口令） | P0 |
| FR-6.2 | 未解锁时，本节全部功能在 UI、菜单、快捷键、托盘中完全不可见 | P0 |
| FR-6.3 | **自动解题**：全局快捷键截屏 → OCR/视觉模型识别题目 → 直接给出答案 | P0 |
| FR-6.4 | 自动解题支持多题连续截取、题目队列、答案历史 | P1 |
| FR-6.5 | **全屏 OCR 术语识别**：对任意应用窗口截屏 OCR，透明覆盖层在原位置标注术语，能力与 FR-4 一致 | P0 |
| FR-6.6 | 覆盖层为鼠标穿透窗口，不影响下层应用正常操作；仅术语区域可交互 | P0 |
| FR-6.7 | **防录屏隐蔽开关**：开启后窗口对截屏与屏幕共享不可见（`WDA_EXCLUDEFROMCAPTURE`），默认关闭（决策 D5） | P0 |
| FR-6.8 | 隐蔽模式下可选隐藏任务栏图标与 Alt+Tab 条目 | P1 |
| FR-6.9 | **自带 Key 的 AI 聊天客户端**：完整对话界面，支持多会话、多模型切换、流式输出、Markdown 与代码高亮 | P1 |
| FR-6.10 | 开发者模式提供 Prompt 调试台：可查看与编辑各功能实际发送的 Prompt | P2 |

### FR-7 大模型接入与配置（全局）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-7.1 | 适配三套协议：OpenAI 兼容、Anthropic 原生、Gemini 原生（决策 D4） | P0 |
| FR-7.2 | 每个 Provider 的 API Key、Base URL、模型名、超时、重试次数全部用户可改（硬约束 C-08） | P0 |
| FR-7.3 | 支持配置多个 Provider 实例并为不同功能分别指定（如术语解释用便宜模型、解题用强模型） | P0 |

| FR-7.5 | API Key 使用 Electron `safeStorage` 加密落盘，禁止明文（决策 D10） | P0 |
| FR-7.6 | 支持本地模型（Ollama / LM Studio）通过 OpenAI 兼容协议接入 | P1 |
| FR-7.7 | 显示 Token 用量与预估成本统计 | P2 |

## 3. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 悬停简释响应 | 缓存/词库命中 < 50ms；LLM 首字 < 1.5s |
| NFR-2 | 全屏 OCR 单轮耗时 | 1080p 全屏 < 800ms |
| NFR-3 | 空闲态资源占用 | CPU < 2%，内存 < 350MB |
| NFR-4 | 录制稳定性 | 连续录制 3 小时不崩溃、不丢帧超 1% |
| NFR-5 | 隐私 | 所有用户内容默认仅本地存储；除用户配置的 LLM 端点外不做任何外发 |
| NFR-6 | 安全 | API Key 加密存储；渲染进程禁用 nodeIntegration，启用 contextIsolation |
| NFR-7 | 无障碍 | 键盘可完整操作术语标注与浮层；符合 WCAG 2.1 AA 对比度要求；浮层支持屏幕阅读器 |
| NFR-8 | 离线可用 | 术语库命中与已缓存解释在断网时可用 |
| NFR-9 | 跨端复用 | 核心逻辑（Provider 层、术语引擎、Repository）与平台层解耦，供手机端复用 |
| NFR-10 | 兼容性 | Windows 10 1903+ 与 Windows 11，x64 与 arm64 |

## 4. 明确不做（第一阶段范围外）

- 手机端 App 实体交付（仅预留接口）
- 浏览器扩展（术语识别走全屏 OCR 与内置阅读器两条路）
- 用户账号体系与服务端（纯本地 + 用户自有存储）
- 自建 ASR / OCR 模型训练
- 团队协作与多人共享

## 5. 验收标准

1. 六大功能模块（FR-1 ~ FR-6）的 P0 项全部可用且可演示。
2. 对外形态下开发者模式功能零泄漏：全局搜索 UI 文本与菜单项无任何解题相关入口。
3. 术语递归下钻实测不少于 5 层，面包屑可正确回退。
4. 马克思主义术语库不少于 200 条，抽样 20 条解释准确。
5. 三套 Provider 协议各自连接测试通过，Key 与 Base URL 改动即时生效。
6. 会议自动录制三态开关行为符合 FR-5.3 ~ FR-5.6。
7. `npm run build` 零错误零类型告警，单元测试通过率 100%。
8. 打包产物在干净 Windows 环境可安装启动。
