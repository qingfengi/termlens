# TermLens 核心阅读流程交付任务

## 用户确认（必读）

### 2026-09-08 最新交互确认（优先于内置阅读器主入口）

> 不太想做成浏览器框架，更像 typeless、输入法。
> 选中文字后快捷键弹出解释；也能开启“选中即解释”。
> AI 自动把文本拆成词语，点击词语、短语或术语查看解释。
> 能继续追问，采用浮窗或侧边栏。
> 不需要必须输入文本；希望像输入法一样，在不同软件里都能使用。

最新入口落实：启动先出现轻量浮窗；读取外部选区后直接显示术语与解释，输入框默认收起，只在用户选择粘贴/编辑时展开。记录阅读器是次级入口。第一版跨软件能力基于操作系统选区接口，不等于承诺所有软件兼容；OCR 不擅自纳入本轮。

主入口改为独立 Windows 桌面选择解释浮窗；内置阅读器作为原文和记录管理入口。默认关闭自动监听，由用户明确开启。使用 Windows UI Automation 读取被选文本，不持续记录全部输入，不读取密码控件，不修改剪贴板。未提供文字选择接口的应用要明确显示不支持或无选择；禁止承诺全软件兼容。该行为属于已授权的应用功能，验收使用专用测试窗口，不读取用户正在使用的其他软件内容。

> 先把术语解释工具搞完，然后再搞热点聚合。
> 如果说涉及比较多的话，你可以直接抽卡。
> 上传到 GitHub 上全都公开，但是不要公开相关的 API 什么的。
> 我认为的话先做最基本的术语识别解释和追问。
> 先完成术语阅读、解释、追问和保存。
> 参考 https://github.com/zarazhangrui/youtube-digest 。

本轮明确范围：内置阅读器、本地术语识别、悬停简释、点击详解、递归追问、阅读记录和对话保存、用户配置 AI 服务、安全验证、独立公有仓库。

原 requirements.md 的语音、会议录制、全屏 OCR、同步和开发者工具保留为后续范围，本轮不以它们的占位页作为完成品交付。基于 D:/TermLens-audit 的现有实现；不覆盖 C 盘其他项目。

## 当前限制

真实第三方 AI 账户尚未用于验收；测试用本地模拟服务验证请求格式和错误路径，不使用个人密钥。输出质量由实际模型和提示内容共同决定，不以模拟响应冒充真实模型效果。

配置与凭据是两个文件：普通异常会回滚，但两次重命名之间的断电/进程崩溃不是完整事务；磁盘故障导致回滚失败会明确报错。这是剩余边界，不宣称已消除。其他尚未验收项包括不同电脑、Word、复杂 PDF、管理员权限窗口与真实模型输出质量。
